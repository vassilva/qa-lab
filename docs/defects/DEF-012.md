## Summary
The test `tests/integration/test_openapi.py` reads the contracts `contracts/*.openapi.yaml` with `import yaml`,
but the PyYAML library was not in `requirements.txt`. Inside the image, pytest stopped while collecting the tests
and the pipeline did not get past the first test stage. The version reached neither QA nor UAT.

## Evidence
```
ERROR collecting tests/integration/test_openapi.py
E   ModuleNotFoundError: No module named 'yaml'
1 error in 0.67s
```

## Analysis
"Works on my machine": in the development environment PyYAML was already installed system-wide,
so the 86 tests passed locally. The Docker image only has what is declared in `requirements.txt`.
This is exactly why the pipeline runs the tests **inside the image** that will be promoted.

## Fix
- `requirements.txt`: `pyyaml>=6.0`.
- Check done: every library imported by the project (app, tests, BDD steps, scripts) is declared.

## Retest
Build #7: the "Component and API tests" stage collected and ran the 86 tests (86/86 passed).

## Prevention
Improvement action: run the tests in a clean environment (the image itself) before delivering a version,
not only in the development environment.

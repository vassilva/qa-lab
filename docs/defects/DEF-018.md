# DEF-018 · New multibranch job "qa-lab" not loaded after the Jenkins update (created on disk, missing in Jenkins)

| Field | Value |
| --- | --- |
| Status | Fixed (in retest) |
| Component | Environment / Pipeline tooling (Jenkins configuration as code) |
| Severity | High |
| Priority | P1 |
| Environment | Lab Jenkins (`qa-lab-tools`), first start after the CI/CD flow change (PR #1) |

## Summary
After `update_tools.ps1` rebuilt Jenkins with the new configuration (multibranch job `qa-lab` instead of
`qa-lab-pipeline`), the resume step failed 36 times with `HTTP Error 404: Not Found` and ended with
"Jenkins did not answer". Jenkins was up, but the new job did not exist for it.

## Steps to reproduce
1. Jenkins running with the old configuration (job `qa-lab-pipeline`).
2. Change `jenkins/casc.yaml` to create a **new** job `qa-lab` (multibranch) and run `scripts\update_tools.ps1`.

## Expected result
Jenkins starts with the new job `qa-lab`; the script enables it and ends with "Tools updated".

## Actual result
- Script: 36 × `Error talking to Jenkins: HTTP Error 404: Not Found`, then "Jenkins did not answer".
- Dashboard: only `qa-lab-pipeline` (disabled); `http://localhost:8090/job/qa-lab/` → 404.

## Evidence (investigation, hypothesis by hypothesis)
| # | Hypothesis | Check | Result |
| --- | --- | --- | --- |
| 1 | The image rebuild failed (old Jenkins still running) | `docker ps` → container created 21:10:05, after the update | Rejected |
| 2 | The configuration was not applied | Dashboard system message is the new one | Rejected |
| 3 | Job DSL error | `docker logs` → `createOrUpdateConfig for qa-lab` at 21:10:36.842, no error after it | Rejected |
| 4 | Multibranch plugins missing | `ls /var/jenkins_home/plugins` → `workflow-multibranch`, `branch-api`, `cloudbees-folder` present | Rejected |
| 5 | Job not written to disk | `ls /var/jenkins_home/jobs/qa-lab` → `config.xml`, `state.xml`, `branches/`, `indexing/` | Rejected |
| 6 | **Start-up order**: the job was created (21:10:36.842) **before** Jenkins loaded the jobs from disk ("Loaded all jobs", 21:10:37.498), so the in-memory job was replaced by the list read earlier | `docker restart qa-lab-jenkins` → job `qa-lab` appears and the resume works | **Confirmed** |

## Analysis
- Severity **High** / P1: the whole pipeline is unavailable until someone restarts Jenkins by hand.
- Only happens when a job is **created** (not updated) by configuration as code on the first start.
- Not caught before: the Jenkins configuration cannot be tested outside the real Jenkins; the change went
  through review and the GitHub Actions check, which do not start Jenkins.

## Fix
- `scripts/jenkins_ctl.py resume`: returns exit code **3** when Jenkins answers but the job does not exist.
- `scripts/update_tools.ps1`: on exit code 3, restarts Jenkins **once** (`docker restart qa-lab-jenkins`)
  and keeps retrying.
- Workaround (before the fix): `docker restart qa-lab-jenkins` then `scripts\update_tools.ps1 -ResumeOnly`.
- Side effect seen: build `qa-lab/main #1`, started by the first branch scan before the restart, failed in
  `Prepare` with `ERROR: No build record qa-lab/main#1 could be located` (orphan build). Run the branch again
  (**Build with Parameters**): build #2 passed end to end (135/135, approval, UAT deploy and smoke).

## Retest
This fix is the first change delivered through the new flow: branch → push (Jenkins branch job + GitHub Actions)
→ pull request → auto-merge → Jenkins `qa-lab/main` → approval → UAT.

## Lesson
Infrastructure changes (CI configuration) need a test of their own: a configuration that is valid can still
fail on the first start. Investigate one hypothesis at a time and record why each one was rejected.

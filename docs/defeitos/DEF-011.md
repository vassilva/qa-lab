## Resumo
O contentor da aplicação tem o cliente PostgreSQL 15 (o do Debian 12), mas os ambientes usavam o servidor PostgreSQL 16.
O `pg_dump` recusa fazer backup de um servidor de versão principal mais recente
(`server version mismatch`), por isso o backup antes de um deploy em UAT falharia precisamente quando fosse preciso.

## Resultado esperado
`bash scripts/backup_db.sh` cria um backup válido em QA e UAT.

## Análise e correção
Encontrado antes de acontecer, ao comparar as versões: `psql --version` no contentor da aplicação (15) vs. a imagem `postgres:16`.
Correção: alinhar o servidor com o cliente (`postgres:15` em `docker-compose.env.yml`). As funcionalidades SQL usadas
(ON CONFLICT, CTE, CHECK, índices) são iguais nas duas versões. Os ambientes `qa` e `uat` são criados de novo, por isso não há migração de dados.
Reteste: `docker exec qa-lab-uat-app bash scripts/backup_db.sh` → "Backup OK".

## Summary
The application container has the PostgreSQL 15 client (the Debian 12 one), but the environments used the PostgreSQL 16 server.
`pg_dump` refuses to back up a server with a newer major version
(`server version mismatch`), so the backup before a UAT deployment would fail exactly when it was needed.

## Expected result
`bash scripts/backup_db.sh` creates a valid backup in QA and UAT.

## Analysis and fix
Found before it happened, by comparing versions: `psql --version` in the application container (15) vs. the `postgres:16` image.
Fix: align the server with the client (`postgres:15` in `docker-compose.env.yml`). The SQL features used
(ON CONFLICT, CTE, CHECK, indexes) are the same in both versions. The `qa` and `uat` environments are created from scratch, so there is no data migration.
Retest: `docker exec qa-lab-uat-app bash scripts/backup_db.sh` → "Backup OK".

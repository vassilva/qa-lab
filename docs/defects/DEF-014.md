# DEF-014 · The tool update script deadlocks with a running pipeline (quiet down pauses the build)

| Field | Value |
| --- | --- |
| Status | Closed |
| Component | Environment / Pipeline tooling |
| Severity | High |
| Priority | P1 |
| Environment | Jenkins |
| Version | 0.6.0-dd39a93 |
| Acceptance criterion | — |
| Risk | T-03 |
| Detected by | Pipeline log (build #10): `Pausing (Preparing for shutdown)` right after "QA · Deploy" |
| Date | 2026-11-03 |

## Summary
The DEF-008 fix put Jenkins in **quiet down** and waited for running builds to finish before rebuilding the tools.
In quiet down, Jenkins also **pauses running Pipeline builds**. The script waited for the build, and the build waited
for quiet down to end: a deadlock. The build stopped after "QA · Deploy" and the script gave up after its time limit,
leaving Jenkins in quiet down.

## Steps to reproduce
1. Commit a change so that a pipeline build starts.
2. While it runs, execute `scripts\update_tools.ps1`.
3. The build log shows `Pausing (Preparing for shutdown)` and the script keeps printing "Waiting for 1 build(s) to finish".

## Expected result
Running builds finish normally; no new builds start; then the tools are rebuilt.

## Actual result
The running build is paused indefinitely; the update never happens.

## Analysis
Assumption in the DEF-008 fix that was not tested: "quiet down lets running builds finish". That is true for
freestyle jobs, not for Pipeline jobs, which pause at the next step. A second, hidden defect was found in review:
the PowerShell function returned the command output together with the exit code, so the success check could never pass.

## Fix
- `scripts/jenkins_ctl.py pause` **disables the pipeline job** (no new builds, not even from SCM polling) and cancels
  any quiet down; running builds carry on. `resume` enables the job again.
- `scripts/update_tools.ps1`: output written to the console instead of being returned; after the rebuild it retries
  `resume` until Jenkins answers; new `-ResumeOnly` option.

## Retest
Update the tools while a build is running: the build finishes, the update follows, the job is enabled again and
picks up the new commit.

## Lesson
A fix for an infrastructure defect needs its own test in the conditions where the defect happened
(here: with a build running), not only on an idle Jenkins.

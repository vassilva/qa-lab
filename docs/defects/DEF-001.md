# DEF-001 · Quantity 10,000 is rejected (maximum limit not included)

| Field | Value |
| --- | --- |
| Status | Open (challenge mode) |
| Component | Order Entry Gateway |
| Severity | Medium |
| Priority | P2 |
| Environment | QA · challenge mode (`QA_LAB_CHALLENGE=1`) |
| Version | 0.3.0-c200193 |
| Acceptance criterion | AC-V01 |
| Risk | R-07 |
| Detected by | BDD scenario `Quantity limits` (example 10000) |
| Date | 2026-11-03 |

## Summary
An order with the maximum allowed quantity (10,000) is rejected as invalid. The limit should be inclusive.

## Steps to reproduce
1. QA environment in challenge mode, business date 2026-11-02.
2. `POST /api/orders` with `{"symbol":"EDP","side":"BUY","qty":10000,"price":4.50}`.

## Expected result
Order accepted (`NEW`, HTTP 201): 10,000 is inside the 1–10,000 range (AC-V01).

## Actual result
`{"status":"REJECTED","reason":"Invalid quantity"}` · HTTP 422.

## Evidence
- Log: `WARNING [OEG] Order O00001 REJECTED: Invalid quantity (BUY 10000 EDP @ 4.5)`
- BDD: `features/01_order_validation.feature` · Outline "Quantity limits" · example `10000` fails; `10001` and `0` pass.

## Analysis
Boundary error (off-by-one) in the Order Entry Gateway validation: the comparison uses "less than" instead of "less than or equal".
Impact: participants cannot send orders of the maximum size; there is no financial loss, hence medium severity.

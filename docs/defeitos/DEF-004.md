# DEF-004 · Prioridade tempo invertida nas compras com o mesmo preço

| Campo | Valor |
| --- | --- |
| Estado | Aberto (modo desafio) |
| Componente | Matching Engine |
| Severidade | Crítica |
| Prioridade | P1 |
| Ambiente | QA · modo desafio (`QA_LAB_CHALLENGE=1`) |
| Versão | 0.3.0-c200193 |
| Critério de aceitação | AC-N03 |
| Risco | R-02 |
| Detetado por | Cenário BDD `Com o mesmo preço, executa primeiro quem chegou antes` |
| Data | 2026-11-03 |

## Resumo
Entre duas ordens de compra com o mesmo preço, é executada primeiro a que chegou **depois**. Nas vendas a regra está correta.

## Passos para reproduzir
1. Ambiente QA em modo desafio, mercado limpo.
2. Comprar 100 EDP a 4.48 (O00001). 3. Comprar 100 EDP a 4.48 (O00002).
4. Vender 100 EDP a 4.48.

## Resultado esperado
O negócio é com **O00001** (chegou primeiro).

## Resultado obtido
`{"buy_order_id":"O00002","sell_order_id":"O00003"}`. O mesmo teste com duas vendas executa corretamente a primeira (O00001).

## Evidências
- Log: `INFO [ME] Negócio T00001: 100 EDP @ 4.48 (compra O00002 / venda O00003)`
- Teste comparativo no lado da venda passa, o que isola o problema na ordenação do livro de compras.

## Análise
A ordenação do livro de compras usa a ordem de chegada ao contrário. Viola a regra preço-tempo, que é a base da equidade de um mercado.
Sem impacto no preço, mas com impacto regulatório e reputacional.

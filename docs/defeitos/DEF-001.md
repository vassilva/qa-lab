# DEF-001 · Quantidade 10 000 é rejeitada (limite máximo não incluído)

| Campo | Valor |
| --- | --- |
| Estado | Aberto (modo desafio) |
| Componente | Order Entry Gateway |
| Severidade | Média |
| Prioridade | P2 |
| Ambiente | QA · modo desafio (`QA_LAB_CHALLENGE=1`) |
| Versão | 0.3.0-c200193 |
| Critério de aceitação | AC-V01 |
| Risco | R-07 |
| Detetado por | Cenário BDD `Limites de quantidade` (exemplo 10000) |
| Data | 2026-11-03 |

## Resumo
Uma ordem com a quantidade máxima permitida (10 000) é rejeitada como inválida. O limite deveria ser inclusivo.

## Passos para reproduzir
1. Ambiente QA em modo desafio, data de negócio 2026-11-02.
2. `POST /api/orders` com `{"symbol":"EDP","side":"BUY","qty":10000,"price":4.50}`.

## Resultado esperado
Ordem aceite (`NEW`, HTTP 201): 10 000 está dentro do intervalo 1–10 000 (AC-V01).

## Resultado obtido
`{"status":"REJECTED","reason":"Quantidade inválida"}` · HTTP 422.

## Evidências
- Log: `WARNING [OEG] Ordem O00001 REJEITADA: Quantidade inválida (BUY 10000 EDP @ 4.5)`
- BDD: `features/01_validacao_ordens.feature` · Esquema "Limites de quantidade" · exemplo `10000` falha; `10001` e `0` passam.

## Análise
Erro de fronteira (off-by-one) na validação do Order Entry Gateway: a comparação usa "menor que" em vez de "menor ou igual".
Impacto: participantes não conseguem enviar ordens do tamanho máximo; não há perda financeira, por isso severidade média.

# DEF-005 · Calendário de liquidação ignora os feriados TARGET2

| Campo | Valor |
| --- | --- |
| Estado | Aberto (modo desafio) |
| Componente | Settlement |
| Severidade | Crítica |
| Prioridade | P1 |
| Ambiente | QA · modo desafio (`QA_LAB_CHALLENGE=1`) |
| Versão | 0.3.0-c200193 |
| Critério de aceitação | AC-L02, AC-L06 |
| Risco | R-03, R-13 |
| Detetado por | Esquema BDD `Cálculo da data de liquidação T+2` (exemplos de feriados) |
| Data | 2026-11-03 |

## Resumo
Os dias de fecho TARGET2 (Natal, 26 de dezembro, Sexta-feira Santa, Segunda-feira de Páscoa, 1 de janeiro, 1 de maio) são tratados
como dias úteis: a data de liquidação cai num feriado e é possível definir um feriado como data de negócio.

## Passos para reproduzir
1. Ambiente QA em modo desafio.
2. Definir a data de negócio 2026-12-23 e executar um negócio de 100 EDP a 4.50.
3. Ver a instrução de liquidação.
4. Tentar definir a data de negócio 2026-12-25.

## Resultado esperado
Liquidação prevista para **2026-12-28** (25 e 26 são feriados, 27 é domingo). A data 2026-12-25 é recusada (HTTP 400).

## Resultado obtido
- `{"instruction_id":"S00001","trade_date":"2026-12-23","intended_settlement_date":"2026-12-25"}`
- `POST /api/business-date {"date":"2026-12-25"}` → aceite (`{"business_date":"2026-12-25"}`).

## Evidências
- Log: `INFO [SETTLEMENT] Instrução S00001 criada ... liquidação prevista 2026-12-25`
- BDD: os exemplos de feriados (Natal e Páscoa) falham; os de fins de semana passam, o que isola o problema nos feriados.

## Análise
O cálculo de dias úteis só exclui fins de semana. Instruções com data num dia em que o T2S está fechado não liquidam e geram
falhas de liquidação e penalizações. Bloqueia a release.
